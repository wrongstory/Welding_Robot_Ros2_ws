## 핵심 결론 (한 줄)
kkw 에는 **QD(조향형) 인터페이스 계층만** 그대로 복사돼 있고, FITO 가 실제로 구동하는 **DD(차동구동, 2WD) 제어 노드는 미이식**이다. QD 로 보이는 것은 "누군가 QD 를 택해서"가 아니라 **FITO 인터페이스 패키지를 원본 그대로(byte-identical) 복사**했기 때문이며, 그 인터페이스가 FITO 안에서도 rewrite 되지 않은 **QD superset** 이기 때문이다.

## 근거 (실측 인용)

### [존재] kkw 이식 범위
- kkw AMR-Motion-Control 하위 = `amr_interfaces` **단독** (노드·safety·guard 미이식).
- `diff -rq kkw/amr_interfaces FITO/src/.../amr_interfaces` → 차이 0 (**바이트 동일 복사**).

### [존재] 인터페이스는 QD(조향/옴니) 형상
`amr_interfaces` 가 담은 어휘 = 조향형 플랫폼 전제:
- `AMRMotionCrab.action` — 측면 이동(lateral translation, heading 유지) = DD 불가 동작
- `AMRMotionTranslate.action` — `current_vx` **와** `current_vy`(측면속도) 분리
- 공통 phase `0=steer_align … 4=steer_return`, goal `hold_steer`/`exit_steer_angle`(조향각)
- feedback `w1_drive_rpm`/`w2_drive_rpm` — 2 구동륜 독립 RPM

### [동작] FITO 실제 노드는 DD(2WD 차동구동)
- `motion_common.hpp` `publishCmdVel(pub, linear_x, angular_z)` — Twist 에 **linear.x + angular.z 만** 발행, `linear.y` 없음 → 옆으로 못 감 = 차동구동.
- 서버 어디서도 `linear.y`/`vy` 미발행 (grep 0).
- `AMRMotionCrab` **서버 미구현** — CMakeLists `amr_motion_control_2wd_node` 에 spin/turn/yaw/translate/translate_reverse/pure_pursuit 만 등록, crab 없음.
- `yaw_control_action_server` 주석: "omega-only control: vy is always 0, heading alignment via **differential steer**".
- `ACS_PLAN.md`: "the 2WD AMR **is differential drive**".

### [동작] 원본 자체가 QD→DD 다운그레이드였음 (smoking gun)
`turn_action_server.cpp`:
- L117-118: `// 원본 대비 변경: IK::compute({v, 0, omega}) → publishCmdVel(v, omega)` / `IK::computeSpin(omega) → publishCmdVel(0, omega)` — **원본은 3-DOF IK(vx, vy, omega) + DualSteerIK = QD**, 이를 2-DOF DD 로 치환.
- L116: `// 원본 대비 제거: Phase 0 (steer align), Phase 4 (steer return), DualSteerIK`
- L58: `// hold_steer/exit_steer_angle 검증 제거: 2WD에서 무시`
- L332: `// Phase 4 (steer return) — 2WD에서 제거: 조향 모터 없음`

즉 FITO 는 **QD 코드베이스를 DD(2WD)로 개조**하면서 `.action`/`.srv` 는 **rewrite 하지 않고 그대로 두고**, DD 노드가 QD 전용 필드(steer/crab/vy)를 무시하도록 처리했다. 인터페이스는 QD superset 으로 남고 구현은 DD subset 이 된 것 — FITO 원본에 내재한 설계 부채다.
