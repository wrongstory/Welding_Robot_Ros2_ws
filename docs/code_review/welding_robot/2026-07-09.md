### Core 인벤토리

#### 1. 목적

`welding_robot/` 는 **용접선(Welding) 인스턴스 세그멘테이션** 모델의 데이터셋 → 학습 → Hailo-8 배포까지 완결된 파이프라인이다 (`hailo/README.md`, `crop_center_640.py` docstring, `train_v8.py` docstring 인용). 구성:

- **데이터셋**: Roboflow `kuk-won-ko/welding-oo2ll` 에서 export 한 1 클래스(`Welding`) 세그멘테이션 데이터. 원본 1280×720 → 중앙 640×640 crop 두 벌 존재.
- **학습**: `yolov8s-seg.pt` 파인튜닝, 640 정사각, mosaic on, patience 조기종료 (실측 331 epoch 수렴).
- **배포**: `best.pt` → ONNX(opset 11) → `hailomz` INT8 컴파일 → `welding_yolov8s_seg_int8.hef` (Hailo-8, 2-context). 온칩 NMS 없이 10개 raw 텐서 출력, 호스트 numpy 후처리.

이 분석의 요청 대상은 **학습 데이터**이며, 데이터를 생성·소비하는 스크립트를 함께 인벤토리한다.

#### 2. 데이터 흐름도 (전체)

```
Roboflow export (Welding.yolov8.zip, 429 files)
   └─ dataset_original/{train,valid,test}/{images,labels}  (148 / 43 / 21, 1280×720, seg 폴리곤)
        └─[crop_center_640.py]  중앙 640×640 crop + 폴리곤 Sutherland-Hodgman 클리핑
             └─ dataset_crop640/{train,valid,test}  (148 / 43 / 21, 640×640)
                  └─[train_v8.py → ultralytics YOLO]  yolov8s-seg.pt, 640, mosaic1.0, patience100
                       └─ runs/segment/…_20260709/weights/best.pt   (Box/Mask mAP@0.5 0.995)
                            ├─[ultralytics export]→ best.onnx (opset11)
                            │    └─[hailo/scripts/compile_hef.sh → hailomz]  calib=crop640/train 148장
                            │         └─ hailo/deploy/welding_yolov8s_seg_int8.hef  (INT8, 106 FPS)
                            ├─[pytorch_ref.py]→ hailo/ref_pytorch/*.npz  (검증 기준, val 43)
                            └─[view_results.py]  polygon 오버레이 시각화 (GT/HEF 비교, 키 조작)
                                 ┊
                  HEF 추론: [infer_hailo_seg.py]  letterbox→infer→DFL decode→NMS→mask 조립
                  정합성:   [compare_hef.py]  HEF vs PyTorch box/mask IoU
```

두 진입 경로: **(A) 오프라인 데이터 준비·학습** (crop→train), **(B) 배포·검증** (export→compile→infer→compare). 공통 자산 = `best.pt` / `dataset_crop640`.

**데이터셋 #212장 — [테스트] 연속 영상 프레임의 split 간 temporal leakage 위험 (High)**
   재현: 프레임 ID 가 14:18:08~14:25:42 연속 캡처. 동일 프레임 ID 중복은 0 이나, 인접 프레임(예: valid `image_141920` ↔ train `image_141921`, ~1초 간격)은 시각적으로 near-duplicate. Roboflow 무작위 split 이 시간 인접 프레임을 train/valid 로 흩뿌리면 valid 가 train 과 독립적이지 않아 **mAP@0.5 0.995 가 과대평가**일 수 있음.
